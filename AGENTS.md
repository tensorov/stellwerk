# Stellwerk Federation — инварианты

## Закон
1. Модель не верифицирует себя. Любое «готово» = ToolAttestation от PolyForge, не текст.
2. TDD: сначала падающий тест, потом код. Коммит без нового теста — отклоняется.
3. Каждая задача = один task packet. Полный план читает только Atlas.
4. Не расширяй скоуп. Нашёл смежную проблему — заведи FINDING, не чини.
5. Не добавляй зависимости. Разрешены только крейты из [workspace.dependencies]
   корневого Cargo.toml (подключать через `workspace = true`). Нужен новый — верни BLOCKED.
6. **Отсутствие данных — это отдельное состояние, а не значение по умолчанию.**
   `unwrap_or(R0)`, `if let Some(..) else { Allow }`, «нет ответа — значит отказ»,
   `Ask` без подтверждения, молчаливый `Deny` в `default`-ветке — все формы
   одного дефекта: неизвестное превращается в разрешение или в отказ, и то и
   другое неотличимо от сознательного решения. Если значение может отсутствовать —
   заведи отдельный вариант (`Classified(..)` / `Unclassified`) и определи его
   поведение явно. Отдельно: «запрещено политикой» и «никто не ответил» должны
   быть различимы в статусе и в evidence.

Lint-политика (исключения в `[workspace.lints.clippy]` или `[lints.clippy]`
крейта) меняется только packet'ом с меткой `contract-change` **и** ADR в
`docs/adr/`: `#[allow(...)]` в коде запрещён безусловно.

## Границы правки
- ≤ 3 файла и ≤ 200 строк diff на один task packet. Больше — верни SPLIT_REQUIRED.
- Не трогай: modules.lock, .github/workflows/, crates/stellwerk-core/src/contract.rs,
  корневой Cargo.toml (только через отдельный packet с меткой contract-change).

**Счёт строк: ADR-0003 (C2), не `wc -l`.** То, что в первом пункте названо
«≤ 200 строк diff», считает `scripts/plan-lint.py`, функция `added_counts`, и
только этот счёт авторитетен. Считаются строки, добавленные коммитом: `src`
логически, без пустых и без строк, начинающихся с `//`; `tests` полностью и
отдельным бюджетом; `.sisyphus/plans/**` в бюджет не входит, это задание
воркеру, а не дифф под ревью. `wc -l` мерило не даёт.

Поле `max_diff_lines` во frontmatter пакета: сырой потолок диффа, и с C2 он
может расходиться. При расхождении вердикт даёт C2, именно его считает линтер,
`max_diff_lines` он не читает. SPLIT_REQUIRED решает C2, а не сырая длина.
Два числа вместо абстракции: packet-09 (M5) дал 555 строк сырого диффа при
`max_diff_lines: 200` и прошёл C2 чистым (src 194 / tests 246); packet-10 (M5)
дал 269 сырых и тоже прошёл чистым (src 15 / tests 250, ровно на потолке).
Разбивай только когда C2 действительно требует, а не когда разошлась сырая
длина. Оба потолка не поднимаются, чтобы пакет влез: и src-200, и tests-250
меняются только packet'ом с меткой `contract-change` и ADR в `docs/adr/`.

**`overlap_waiver: C9` (условный, не бланковый).** C9 ловит два пакета разных
milestone, заявляющих один файл, когда порядок не объявлен ни в одном
`depends_on`; пересечение внутри одного milestone это дело C1. Waiver:
пересечение разрешено для пакетов рефакторинга и усиления тестов. Прецедент:
M5/packet-21, 22 и 23 намеренно заново берут файлы, которыми владеют ранние
milestone (`session.rs`, `events.rs`, `approval.rs`); пересечение фиксируется
строкой `overlap_waiver:` в пакете, и линтер её принимает. Условие, при котором
waiver безопасен: строго последовательное исполнение в одном worktree. Пока
пакеты идут по очереди в одном worktree, двое из них не живы одновременно, и
устаревшая база не может оказаться причиной отказа. Оба условия (характер
пакета и последовательность) обязательны вместе; выпало любое, C9 снова в
силе, а не «формальность».

## Источник истины для пакетов

Канон пакетов — **`.sisyphus/plans/M*/packet-*.md`**. Только эти файлы являются
входом раздачи; воркер читает вложенные каталоги `M1/`, `M2/`, `M3/`, `M4/`.

`.omo/plans/` — зеркало OMO, **не** источник. Оно аддитивно по созданию и слепо
по правкам: новые пакеты в него попадают, а изменения существующих — нет. На
одинаковом наборе пакетов канон даёт 0 нарушений, а зеркало — 10 (F-2026-09-27-12).
Раздавать из зеркала нельзя: воркер получит пакет с несуществующей зависимостью.
Снятые версии лежат в `.omo/plans/_archive/` и в раздачу не попадают.
`plan-lint` проверяет расхождение зеркала с каноном (C8) и печатает его всегда.

## Протокол завершения
RED   -> покажи вывод падающего теста
GREEN -> покажи вывод проходящего теста
PROOF -> evidence_append(ModelClaim) + evidence_verify(cmd=<точная команда теста>)
  Для пакета, выполненного в worktree, — ВАРИАНТ B, а не исключение:
  evidence_verify исполняет команду в главном рабочем каталоге, где до merge
  лежит старая ревизия, и возвращает её результат. Поэтому код worktree в
  принципе не аттестуем до попадания в main, а «гейт до коммита» и «коммит до
  гейта» образуют замкнутый круг. Канон: merge --no-ff -> evidence_verify на
  main -> gate_evaluate -> отдельный коммит `chore(evidence): attest <packet>
  after merge` с chain_tail.
  Запрещено: аттестовать на main заглушку, пока реализация живёт только в
  worktree; аттестовать командой, не относящейся к пакету; объявлять гейт
  пройденным без `gate_evaluate`.
  **Тест-сьютку гонять на main ДО merge, а не после.** База воркерского worktree
  отстаёт от main, и на ней расхождение не видно: INFRA-04 (F-26) смержили с
  фикстурой на «красном» бинаре `session_contract`, который к тому моменту уже
  позеленел в M3-12a; в worktree оба выглядели красными, на main сьютка упала
  5/2, и мерж пришлось отвергать. Порядок всегда сначала main, потом merge.
GATE  -> gate_evaluate; если fail — не отчитывайся об успехе

## Формат ответа (последний блок, всегда)
STATUS: DONE | BLOCKED | SPLIT_REQUIRED | FINDING
FILES: <список>
TEST: <точная команда>
EVIDENCE: <chain tail hash>

## Запрещено
Правки без теста, «рефакторинг заодно», подавление предупреждений, #[allow(...)],
#[ignore], skip тестов, мок вместо реализации без пометки в packet, cargo add.
команды, печатающие resolved config или секреты (opencode debug config,
cat auth.json, env | grep KEY и подобные).
