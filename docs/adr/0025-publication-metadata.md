# ADR-0025: метаданные публикации — на workspace, `publish = false` буквально в каждом манифесте

Статус: принят
Дата: 2026-11-22
Пакет: publication-readiness / task-2
Связано: AGENTS.md — границы правки (корневой `Cargo.toml` только через отдельный
packet с меткой `contract-change`); ADR-0028 (исполняемая приёмка артефактов
публикации)

## Проблема

Проект готовится к публичной публикации в `tensorov/stellwerk`. Для этого
нужны машиночитаемые метаданные пакета (описание, репозиторий, домашняя
страница, readme, авторы) и однозначное правило, запрещающее случайную
публикацию в crates.io. Без явного решения метаданные расползаются по
манифестам, а запрет публикации может быть выражен неочевидно (наследование,
workspace-level `publish`, комментарий вместо поля), что делает проверку
хрупкой и допускает тихую ошибку.

## Решение

1. **Метаданные публикации живут в `[workspace.package]` корневого
   `Cargo.toml`.** Канонические поля: `description`, `repository`, `homepage`,
   `readme`, `authors`. Существующие поля `edition`, `license`, `rust-version`
   сохраняются без изменения смысла и значения.

2. **`publish = false` записывается буквально в каждом из 7 манифестов.**
   Каждый crate/xtask манифест содержит собственную строку `publish = false`
   в своей секции `[package]`. Это относится ко всем членам workspace:
   `crates/stellwerk-core`, `crates/stellwerk-registry`,
   `crates/stellwerk-store`, `crates/stellwerk-task`,
   `crates/stellwerk-gateway`, `crates/stellwerk-cli`, `xtask`.

3. **Наследование workspace для `publish` не используется.** Запрещены формы
   `publish.workspace = true`, `package.publish.workspace = true` и любой
   иной механизм, при котором запрет публикации выводится косвенно. Причина:
   буквальное поле видно при локальном чтении одного манифеста и проверяется
   простым текстовым/структурным тестом без интерпретации наследования.

4. **Workspace-level `publish` не вводится.** `[workspace]` не получает поле
   `publish`; запрет выражается только на уровне конкретных пакетов (п.2).

5. **Проверка — исполняемая.** Соответствие метаданных и запрета публикации
   подтверждается командами приёмки (см. ADR-0028), а не декларацией в тексте.

## Последствия

- Любой новый crate в workspace обязан при добавлении получить literal
  `publish = false` в своём `[package]`; отсутствие поля — дефект публикационной
  оболочки.
- Инструменты и ревью проверяют 7 манифестов напрямую; число манифестов
  меняется только вместе с составом workspace members.
- Метаданные имеют один источник истины (`[workspace.package]`), поэтому
  расхождение описания/репозитория между crate'ами исключено на уровне
  канонического поля.
- Изменение корневого `Cargo.toml` в этой области — `contract-change` и требует
  ADR/пакета по правилам AGENTS.md.

## Что запрещено

1. Писать `publish.workspace = true` или полагаться на наследование для запрета
   публикации.
2. Добавлять `publish` в `[workspace]` как замену literal-полям в манифестах.
3. Убирать или переименовывать существующие ключи `[workspace.package]`
   (`edition`, `license`, `rust-version`) в рамках публикационной подготовки.
4. Добавлять зависимости или менять `[workspace.dependencies]`/lints под видом
   публикационных метаданных.
5. Публиковать в crates.io: `publish = false` — инвариант, а не временный флаг.

## Когда пересматривается

Если проект примет решение публиковать crate'ы в crates.io, потребуется
отдельный пакет с меткой `contract-change`, новый ADR, явный список публикуемых
пакетов, политика версионирования и проверка, что ни один внутренний crate не
публикуется случайно. До такого решения этот ADR остаётся в силе.
