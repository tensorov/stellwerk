# Control-run exports

Реестр контрольных прогонов воркера. Каждый прогон — доказательство того, что пакет
из плана закрывается дешёвой моделью через `stellwerk-dispatch` (sandbox → loop_guard →
validity_gate). Код прогонов **не** является источником истины: решённые пакеты
раздаются заново и живут в main только после приёмки интегратором.

## Состав каталога прогона

| файл | что это |
|---|---|
| `packet.md` | пакет, который был исполнен (копия `.sisyphus/plans/M1/packet-03.md`) |
| `validity.json` | вердикт лаунчера — источник истины по «прогон состоялся» |
| `metrics.json` | сводные метрики, посчитанные разбором `run.jsonl` |
| `sandbox.diff` | фактический дифф воркера |
| `sandbox.numstat` | счётчики строк диффа |
| `RESULT.md` | приёмка, выполненная интегратором (воркер свой отчёт не писал) |
| `git-show-merge-stat.txt` | состояние main относительно прогона (merge-коммита нет) |

## Как читать расхождение метрик

`validity.json` (gate) и `metrics.json` (разбор потока) дают разные числа:
gate считает `turns=20`, `input_cum=99048`, мой разбор — `turns=9`, `input_cum=36242`.
Причина — разные правила подсчёта (gate суммирует по событиям сессии, включая
повторы). **Для вердикта VALID/INVALID источник истины — `validity.json`.**
`metrics.json` полезен ради `peak_context_tokens` (13 087), которого gate не отдаёт.

## Чего здесь нет и почему

- **`run.jsonl` не копируется** (484K): весит больше всей остальной evidence;
  воспроизводим из песочницы, путь указан в `RESULT.md`.
- **merge-коммита нет** ни у одного прогона: политика проекта запрещает коммит без
  явного указания владельца. Прогоны либо переигрываются фазой 6, либо ждут решения.
