# stellwerk-attested-autonomy - Work Plan

## TL;DR (For humans)

**What you'll get:** A local unattended loop that turns one owner-approved policy into a sandboxed code change, commits it on a throwaway branch, runs the checks in isolation, attests the trusted check report through PolyForge, and stops for a human to accept the result. A small generated Rust project proves the loop end to end.

**Why this approach:** The owner delegates a bounded class of work once, not every run. The model never approves itself: a deterministic admission check gates the plan, the pre-effect gate **and** `apply` enforce the exact `AutoPlan.allowed_changes` (not merely policy `allowed_paths`), and PolyForge remains the only source of truth for “done”.

**What it will NOT do:** No auto-merge to `main`. No parallel or remote workers. No replacement of human `Validation` with model text. No claim that PolyForge directly attests every untrusted test process; it attests a trusted verifier’s report bound to the commit and diff.

**Effort:** XL
**Risk:** High - the opencode bridge, plugin coverage, check-report attestation, and cross-repo PolyForge validation path are all load-bearing and must fail closed.
**Decisions to sanity-check:** opencode is primary; worker model is fixed; validation is added to PolyForge CLI; checks run without network/token/PolyForge and their report is attested by a trusted verifier; the pilot is a generated fixture, not a production repo.

## Scope
### Affected user and ideal state
The affected users are: the **owner** who delegates a bounded class of changes once and must retain final acceptance; the **operator** who runs one local loop and needs a replayable artifact; and the **downstream worker/agent** that consumes the plan and must not be able to widen its own authority.

| ID | Ideal state | Why it matters |
| --- | --- | --- |
| IS-1 | The owner signs one `AutonomyPolicy`; each run is admitted deterministically without per-run human approval. | Unattended work is only legitimate when the human delegates bounded authority once, not when a model approves itself. |
| IS-2 | The worker cannot write outside the admitted paths, run a shell, fetch the network, or load an untrusted gate. | A sandbox that can be widened from inside is not a boundary. |
| IS-3 | The result is committed on an isolated branch and never auto-merged to `main`. | The owner keeps the merge decision even when execution is unattended. |
| IS-4 | Missing or unparsable checks fail closed; changed-line coverage and mutation score are recorded in a trusted report, not prose. | “No data” must never become “pass” (law 6). |
| IS-5 | A human `Validation` is explicit, attributable, and distinct from model text; only it can close the gate. | PolyForge is the sole source of truth; model output is a claim. |
| IS-6 | One generated Rust fixture proves the loop from failing test to `AwaitingHumanValidation`, with a replay command. | A platform without a real end-to-end proof is only a diagram. |

### Must have
- Durable single-run state for one repo/worktree, with explicit states for planning, admitted, running, checks-failed, evidence-failed, awaiting-human-validation, validated, done, refused, and aborted.
- Owner-signed `AutonomyPolicy` in `<repo>/.stellwerk/autonomy.toml`; parse, validate, digest, and deterministic plan admission.
- `stellwerk auto <repo> --goal <text>`: planner -> admission -> worktree -> sandbox copy -> opencode worker -> apply -> commit -> isolated checks -> trusted check report -> PolyForge `verify`/`gate` -> `AwaitingHumanValidation`.
- opencode worker inside `bwrap --unshare-net`; the HTTP-to-UDS model bridge runs **inside** the sandbox netns on `127.0.0.1:4096` and reaches the host `model.sock` through a bind-mounted Unix socket.
- Mandatory pre-effect gate plugin loaded from a trusted read-only path with a pinned SHA-256; `bash`, `webfetch`, `task`, MCP, and external plugins are disabled.
- Dedicated git worktree and branch; host applies only the allowed diff and commits; never merges to `main`.
- Checks run in a separate bwrap with no network, no tokens, no PolyForge/ledger access, and no host `.git`; the commit step writes `<run>/change.diff` from the committed `git diff-tree`, and the check runner writes `<run>/checks/checks.json` with the policy digest.
- A trusted `stellwerk-check attest --policy ... --policy-digest ... --claim-commit ... --claim-diff-sha256 ... --claim-policy-digest ... --claim-report-sha256 ...` verifier validates the claim binding, policy digest, report schema, commit/diff binding, coverage, and mutation thresholds **without running untrusted code or spawning children**.
- PolyForge `ModelClaim` + `ToolAttestation` for the trusted check report + `gate_evaluate`; after evidence is appended, persist `TaskStatus::EvidenceSubmitted` via `lifecycle::advance`; after `pf gate --required verified`, persist `TaskStatus::Verified` via `lifecycle::advance`; the PolyForge-derived `EvidenceStatus` is `AwaitingHumanValidation` (computed by `evidence_status`, never stored); the local durable marker is `RunState::AwaitingHumanValidation`.
- Human `stellwerk accept <run-id> --bundle <run>/bundle/manifest.json --validator <owner> --rationale <text> --confirm accept` appends `Validation` through a new PolyForge CLI path; then `pf gate --required validated`; only then persist `TaskStatus::Verified -> Validated -> Done` via `lifecycle::advance` and `RunState::Done`.
- Evidence bundle: diff, trusted report, command outputs, hashes, gate result, verified seq, bundle hash, replay instructions.
- One generated Rust pilot repo with a known failing test; `pilot/run.sh` creates it in `${TMPDIR:-/tmp}`, runs the loop, and prints the bundle + replay command.

### Trust and evidence binding
The evidence chain is deliberately split into two environments:

1. **Untrusted execution:** `stellwerk-check run --worktree <commit-worktree> --run-id <run-id> --commit <commit-sha> --policy <worktree>/.stellwerk/autonomy.toml --diff <run>/change.diff --out <run>/checks` executes the policy’s acceptance commands in `bwrap --unshare-net` over a verification copy with no `.git`, no network, no token, and no PolyForge/ledger mount. It writes `<run>/checks/worktree/` (copy without `.git`), `<run>/checks/change.diff`, and `<run>/checks/checks.json`; the report is written by the trusted runner, not by the test process. `change.diff` is produced by todo 16 **after** the commit with exactly `git diff-tree --root --no-commit-id --no-ext-diff --binary -p <commit_sha> > <run>/change.diff`, and todo 17 copies it, never recomputes it from a `.git`-less copy.
2. **Trusted attestation:** `stellwerk-check attest --policy <policy> --policy-digest <digest> --report <run>/checks/checks.json --commit <sha> --diff <run>/checks/change.diff --claim-commit <sha> --claim-diff-sha256 <64-hex> --claim-policy-digest <64-hex> --claim-report-sha256 <64-hex>` validates the claim binding, the owner policy digest, the report schema, the commit/diff hash, every command’s exit code, the changed-line coverage, and the mutation threshold. It does **not** execute project code, spawn children, read the network, or read a token.
3. **PolyForge:** `pf append model_claim <json> --task <task> --commit <sha> --diff <hash>` creates the claim; `pf verify <task> --claim <seq> --tool "stellwerk-check" -- --policy <policy> --policy-digest <digest> --report <run>/checks/checks.json --commit <sha> --diff <run>/checks/change.diff` reads the claim payload, injects `--claim-commit`, `--claim-diff-sha256`, `--claim-policy-digest`, and `--claim-report-sha256`, then runs `attest` in the commit worktree at the claimed commit. A missing or malformed claim payload is a hard error before spawn; a mismatch is a non-zero verifier result and no `Verified` append. PolyForge records the committed diff (`git diff-tree --root --no-commit-id --no-ext-diff --binary -p <commit>`) and appends `ToolAttestation`. It does not create a detached worktree or scrub the host env; the verifier is trusted, does not execute project code, and the only path that executes untrusted tests is `stellwerk-check run` inside bwrap. Todo 2 fixes `current_git_state` so a clean committed change matches the claim diff.
4. **Gate:** after the evidence append, persist `TaskStatus::EvidenceSubmitted` via `lifecycle::advance`; `pf gate <task> --required verified` must pass; then persist `TaskStatus::Verified` via `lifecycle::advance`; persist `RunState::AwaitingHumanValidation` only after the bundle is written and `bundle_path` is `Some`. Do not persist `EvidenceStatus`; it is derived from the PolyForge chain by `evidence_status`.
5. **Human validation:** `pf validate <task> --verified <seq> --bundle <run>/bundle/manifest.json --worktree <run>/worktree --policy-digest <digest> --validator <owner> --rationale <text>` binds the validation to the bundle manifest hash, policy digest, commit, diff, and verified seq; then `pf gate <task> --required validated`; only then persist `TaskStatus::Verified -> Validated -> Done` via `lifecycle::advance` and `RunState::Done`.

This is an explicit trust boundary: PolyForge attests the trusted verifier’s report, not each test process. The report is produced in isolation and bound to the committed SHA/diff; a missing, empty, or mismatched report fails closed.

### `checks.json` contract (exact)
`checks.json` is written only by `stellwerk-check run` after every acceptance command and both metrics finish:
```json
{
  "schema_version": 1,
  "run_id": "<run-id>",
  "policy_digest": "<64-hex>",
  "commit_sha": "<40-hex>",
  "diff_sha256": "<64-hex>",
  "commands": [
    {"argv": ["cargo","test","--quiet"], "exit_code": 0, "duration_ms": 1234, "stdout_sha256": "<64-hex>", "stderr_sha256": "<64-hex>"}
  ],
  "coverage": {"changed_lines": 1, "covered_changed_lines": 1, "percent": 100.0},
  "mutation": {"caught": 1, "missed": 0, "unviable": 0, "percent": 100.0}
}
```
`attest` requires `schema_version == 1`, `policy_digest` equal to the `--policy-digest` argument, to the `--claim-policy-digest` argument, and to the recomputed `AutonomyPolicy::digest()` of `--policy`; every policy acceptance command exactly once (using the same strict whitespace parser as policy/admission); all exit codes `0`; `report.commit_sha == --commit == --claim-commit`; `report.diff_sha256 == sha256(<--diff file>) == --claim-diff-sha256`; the report file SHA-256 equals `--claim-report-sha256`; `coverage.changed_lines > 0`; `mutation.caught + mutation.missed > 0`; and both percentages at or above the policy thresholds. Missing, empty, malformed, duplicated, or extra commands are distinct `AttestError` variants; a missing/malformed claim binding is a distinct error; none defaults to pass.
