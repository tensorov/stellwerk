# M5 — ЯДРО УПРАВЛЕНИЯ: Stellwerk как глубокий Pi extension

Цель milestone: получить работающую петлю «задача → план → пакет → песочница → прогон →
доска → память». Периферия (PDF, Telegram, соцсети, HA-watchdog, mutation-гейты как
отдельный инструмент) уходит в M6.

## Что установлено исследованием Pi (меняет реализацию, не направление)

| Ожидание | Факт | Следствие |
| --- | --- | --- |
| «deep plugin» | термина нет; есть `extension` | называем extension, всю функциональность держит он |
| «Pi task tool» | встроенных tool'ов ровно `bash, edit, find, grep, ls, read, write`; `README.md:19` прямо пишет, что sub-agents и plan mode пропущены | **task tool пишем сами** через `pi.registerTool` |
| «isolated worktrees» | слово `worktree` в `coding-agent/docs/` — 0 вхождений; есть только git-дедуп контекста и статус-бар | изоляция = процесс + `cwd` + наша bwrap-песочница; worktree не нужен |
| «typed results» | результат tool'а = `{content, details}` (+ `structuredContent` при `outputSchema`) | типы держим сами в `details` |
| MCP как граница | `registerMcpServer` поддерживает **только** stdio и streamable-HTTP; in-process нет | `stellwerk-gateway` остаётся отдельным сервисом, не встраивается в Pi |
| Локальный vLLM/SGLang | `pi.registerProvider({baseUrl, apiKey, api})`, `apiKey: "$ENV"` | Cyber-Tiel подключается локально, токен через env-переменную |
| Стабильность API | заявления о стабильности нет; `experimental/` помечен явно | версия Pi запинена и проверяется на старте |

Проверено по репозиторию `earendil-works/pi`; версия `v0.87.0` — реальный тег, но текущая
`v1.0.2`, и scope переехал `@mariozechner/*` → `@earendil-works/*` (legacy-алиасы сохранены).

## На чём стоит lane plugin — проверка по пакетам 01–06

Ни один пакет lane plugin не опирается на примитив, которого нет в Pi. Проверка по каждому:

- **01** — загрузка extension и сверка версии. Примитив: загрузка модуля расширения. Реален.
- **02** — engine adapter целиком в `stellwerk-task`; Pi в нём одна реализация за трейтом.
  Примитивов Pi не требует вовсе, поэтому замена движка ничего не ломает.
- **03** — субагент. **Здесь уточнение, важное для всей схемы.** Субагенты Pi не
  используются: встроенного task tool нет, и мы его не имитируем. Наш tool сам порождает
  `pi --mode json -p --no-session` — так же, как это делает референсный пример в
  репозитории Pi. **Изоляцию даёт не Pi, а наш runtime:** `07a`–`07c` задают границу файловой
  системы и сети, `08` ограничивает набор инструментов, `09` убирает пути к токену.
  Worktree не применяется нигде, потому что ядро Pi его не предоставляет.
- **04, 05** — роли, ритуал и классификатор целиком наш код; примитивов Pi не касаются.
- **06** — панель. Примитив: компонент в интерактивной области. Он даёт контроль
  **временно**, а не захват экрана, поэтому панель не предполагает постоянства и в
  режимах без интерфейса не создаётся. Цели «захватить экран» пакет не ставит.

**Что это значит для формулировки «Pi становится диспетчерской».** Точнее: Pi не
становится диспетчерским сам — мы регистрируем в него инструмент, который им становится.
Диспетчерская логика (кто, что, в каком порядке, с какими правами) живёт в
`stellwerk-task`; Pi предоставляет цикл агента и интерфейс. Если API расширений перестанет
давать нужные точки, это документированный повод для запасного пути «свой TUI поверх того
же API», уже помеченного DEFERRED.

## Пин версии и scope Pi

| Lane | Версия | Scope | Почему |
| --- | --- | --- | --- |
| plugin (01–06) | v1.0.2 | `@earendil-works/*` | пишем под актуальный API; scope переехал, `@mariozechner/*` — legacy-алиас |
| боевой воркер, packet-replay | 0.87.0 | `@mariozechner/pi-coding-agent` | не трогаем: на нём измерены overhead, loop guard и budget guard |

Расхождение осознанное и временное. Замеры overhead и работа guard относятся к 0.87.0 и под
v1.0.2 не перекалибровываются: перенос цифр без замера дал бы ложную точность.


## Карта lanes

```
Lane A  plugin          01→02→03→04→05→06      ядро Pi, сплошной поток
Lane B  runtime         07a→07b→07c→08→09→10   песочница и границы доверия
Lane C  board           11→12→13→14→15         доска и карточки
Lane D  memory          16→17→18               память, ETA, мутационный гейт
Lane E  foundations     19→20                  rollback и токены стиля
```

Где параллельно: Lane B не ждёт Lane A — песочница и границы доверия пишутся против
интерфейса, который объявляет 02. Lane C ждёт только 11 (миграции). Lane D ждёт 16.
Lane E ни от чего не зависит и идёт первым, потому что дешевле всего.

**Критический путь:** 01 → 02 → 03 → 07c → 08 → 11 → 12. Это путь до первого настоящего
прогона задачи агентом.

## Границы пакетов

ADR-0003: ≤3 файла на пакет; `src` ≤200 логических строк на файл; `tests` ≤250 полных
строк на файл, отдельный бюджет. Пакет меняющий критический крейт обязан нести
`mutation_threshold`, и падение порога — FAIL, а не предупреждение.

Критические крейты для M5: `stellwerk-gateway` (решения о доступе) и `stellwerk-task`
(исполнение и одобрение). Реестр, store и core в mutation-гейт M5 не входят — это M6.

## Порядок выдачи

Пакеты выдаются по порядку номеров внутри lane. Разные lane можно раздавать
параллельно разным воркерам, кроме случаев, указанных в `depends_on`.

## Что M5 не доказывает

PASS-прогон задачи не доказывает полноту acceptance. Регрессия, найденная проходом,
не чинится по ходу: она FINDING. Исторический RED не воспроизводится автоматически —
фактический результат и историческое ожидание показываются раздельно.
