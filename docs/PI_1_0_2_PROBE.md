Дата: 2026-10-05. Автор: Prometheus. Статус: результат пробы, не план.

## Границы пробы: что и чем мерялось

**Читалось:** исходники Pi 1.0.2 (`package.json` → `"version": "1.0.2"`), репозиторий
`earendil-works/pi`, HEAD `2003871`. Путь: `/tmp/opencode/pi`.

**Не могло быть измерено:** на машине установлена **Pi 0.87.0** (`pi --version` → `0.87.0`,
`~/.pi/agent/bin/pi`). Pi 1.0.2 не установлена, а установка требует сети. Поэтому
**пункт (c) про `context_input` не измерен** — для замера нужны Pi 1.0.2 и два доступных

подмена замера догадкой не выглядела как результат.

Сводка внешней версии 0.87 → 1.0.2, приложенная владельцем, принята как **гипотезы** и
ни один её пункт не перенесён в план без проверки.

## a. Codemode — ПОДТВЕРЖДЕНО, вызовы проходят через хук

**Отключаем ли для сессии — да.** Codemode включается только явно: `--tools` без
`codemode` для одного запуска либо `defaultTools` без него (`docs/cli.md:148-161`).
Встроенным он не является.

**Проходят ли вызовы через хуки расширений — да, включая блокирующий.** Путь:

- `docs/cli.md:168` — скрипт ходит в инструменты как `tools.<name>(args)`;
- `types.ts:494-509` — дословно: *«Callable means callable from other tools through
  `ctx.executeTool()`, as the `codemode` tool does»*;
- `agent-session.ts:702` — `_executeNestedToolCall`;
- `agent-session.ts:629` — комментарий дословно: *«`tool_call` handlers.
  `parentToolCallId` is set for calls another tool made»*;
- `agent-session.ts:644` — `parentToolCallId` действительно проставляется.

Значит запрет «вызов инструмента из Codemode без прохождения через gateway» выполним
нашей проверкой: хук `tool_call` срабатывает, а `parentToolCallId` позволяет отличить
codemode-источник и отказать по более строгому правилу.

**Следствие для плана:** Codemode не запрещается целиком — запрещается его включение в
рабочих и операторских сессиях, а вызовы, пришедшие через него, обязаны отличаться.

## b. MCP — ПОДТВЕРЖДЕНО, проектный конфиг запретим

`docs/mcp.md:32` дословно: *«Pi reads user-level servers from `~/.pi/agent/mcp.json` and
project servers from `.pi/mcp.json`. Project configuration is read only after project trust
is granted. A project entry replaces a user-level entry with the same name.»*
`docs/cli.md:321` — проектные файлы читаются только для доверенных проектов.
`docs/cli.md:278` — `-na`, `--no-approve` игнорирует выдачу доверия.

Два следствия:

1. **Проектную конфигурацию можно запретить** — не выдавать доверие и не передавать
   `--approve`. Это должно быть безусловным, а не настройкой.
2. **Имя замещается.** Запись в `.pi/mcp.json` с именем пользовательского сервера
   подменяет его. Поэтому «положенный в рабочий каталог конфиг не подключается» —
   не паранойя, а закрытие конкретного вектора.

## c. Deferred tool loading — ПОДТВЕРЖДЕНО частично, замер НЕ ВЫПОЛНЕН

Работает с инструментами расширения: `deferred` — одно из значений `ToolExposure`
(`types.ts:509`), то есть применимо к нашим инструментам. Находится через `tool_search`,
который **выключен по умолчанию** (`docs/cli.md:172`).

**Замер `context_input` не выполнен** — см. «Границы пробы». Требуемые конфигурации
(только встроенные; + наш набор; + deferred) спроектированы, числа не получены.
Сравнение токенов разных моделей между собой запрещено и не производилось.

## d. Virtual models — ПОДТВЕРЖДЕНО, политика остаётся у нас

`docs/virtual-models.md:9` — маршрутизатор отображает пару (виртуальная модель,
уровень мышления) в физическую для **каждого запроса**. `:25` — провайдеры получают
только физические модели.

Значит маршрут по роли задаёт **наше расширение**, и запрет fallback для Personal
проверяется в **нашем коде**: Pi лишь исполняет то, что вернул маршрутизатор, и своего
понятия «персональных данных» не имеет. Политика остаётся в Stellwerk — это подтверждено.

## e. Fullscreen TUI — ПОДТВЕРЖДЕНО ЧАСТИЧНО, опровержения нет

Полноэкранного API нет. `docs/tui.md:15` — `ctx.ui.custom()` это *«Temporary interactive
screen or overlay»*; `tui.md:66` — *«temporarily gives one component control of the
interactive area»*; `tui.md:74` — работа завершается через callback.

Постоянный контент у редактора — отдельный слот: `ctx.ui.setWidget()`
(`docs/tui.md:13`, *«Persistent content near the editor»*).

**Следствие для плана:** панель 06 должна строиться на `setWidget()`, иначе она исчезнет.

**Исправление собственной ошибки.** Первая редакция этого документа дала пункту (e)
вердикт «ОПРОВЕРГНУТО». Это было неверно: прочитано доказало лишь, что `custom()`
временный, а `setWidget()` постоянный. Отсутствие полноэкранного API в документации не
доказывает его отсутствия в коде — я прочитал первое и объявил второе. Владелец
поправил. Полноэкранный API **не опровергнут**, и недостижимость панели при его
отсутствии была бы поводом вернуться к решению о своём TUI, а не выводом о
невозможности.
