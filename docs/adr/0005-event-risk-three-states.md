# ADR-0005 — риск события получает три состояния, а не пол `RiskClass` и не `Option`

Статус: предложен
Дата: 2026-09-30
Решение владельца: EventRisk contract-change (2026-09-30)
Находка: F-2026-09-29-68 (соседняя, тот же закон 6 в другом месте), F-2026-09-30-72

## Проблема

**Посылка владельца требует поправки, и поправка меняет дело из мелочи в необходимость.**
`Event.risk` — не `Option<RiskClass>`, а голый `RiskClass`:

```
crates/stellwerk-core/src/contract.rs:107    pub risk: RiskClass,
```

`#[serde(default)]` в этом структуре есть, и стоит он на `payload` (`:109`), а не на `risk`.
То есть дефолта на риске нет, и добавлять его нельзя — это уже соответствует требованию.

Но если поле не `Option`, то **каждое** событие обязано заявить конкретный класс R0–R5, включая
события, у которых действия нет. А такие источники есть: `EventSource` (`contract.rs:74`)
перечисляет `Manual`, `OpenCode`, `Kanban`, `Startup`, `Calendar`, `Hermes`, `System`. Событие
`Startup` с `risk: RiskClass::R1` — это ложь в поле, и она неотличима от правды. Это и есть
настоящий дефект, и `NotApplicable` нужен не для красоты, а чтобы ложь стала невозможной.

Второе: неизвестный риск **уже схлопывается в выдуманное значение**, и место схлопывания
подписано как требующее contract-change:

```
crates/stellwerk-task/src/runner.rs:532-537
fn column_risk(risk: ToolRisk) -> RiskClass {
    match risk {
        ToolRisk::Classified(class) => class,
        ToolRisk::Unclassified => RiskClass::R1,   // :535
    }
}
```

Комментарий над функцией (`:526-531`) прямо называет это дырой и говорит, что закрыть её —
значит сделать риск события непустимым, а это пакет с меткой `contract-change`. Этим ADR и
занимается.

## Что уже есть в дереве и меняет решение

**Трёхвариантный `EventRisk` не будет первым.** Почти идентичный тип уже существует:

```
crates/stellwerk-gateway/src/permission.rs:32-38
#[derive(Debug, Clone, Copy, PartialEq, Eq)]      // ← без Serialize/Deserialize
pub enum ToolRisk {
    Classified(RiskClass),
    Unclassified,
}
```

Он разошёлся по трём местам прода: `gate.rs:22`, `mount.rs:33`, `runner.rs:267`, и на проводе
проходит через рукописный модуль `risk_wire` (`session.rs:529`) вместо derive. Так что в дереве
уже **два словаря риска**: `ToolRisk` (осведомлён о неизвестном) и `RiskClass` в `Event`
(неосведомлён). `EventRisk` либо вытесняет `ToolRisk`, либо встаёт рядом с ним — и это решение
меняет радиус правки вдвое, см. «Открытая развилка».

**Формат на проводе — голая строка.** У `RiskClass` (`contract.rs:30`) нет `#[serde(rename_all)]`,
поэтому в JSON он лежит как `"R3"`. Старая строка в базе — `"risk":"R3"`, а не объект. Отсюда:
производный `Deserialize` на `EventRisk` **не сломает старые строки только если принять
внешне-тегированный объект** `{"Classified":"R3"}`, что не совпадёт. Значит нужен рукописный
десериализатор, и прецедент в дереве есть — тот же `risk_wire`.

**Механизм миграций есть, изобретать не надо.** `migrations.rs:6-11` — список
`MIGRATIONS: &[(&str, &str)]` с `include_str!`, применяется в `sqlite.rs:91-122` через таблицу
`schema_migrations`. Прецедент `ALTER TABLE` — `0003_payload.sql:4` и `0004_data.sql:5`. События
лежат в `events.data` (`TEXT`), пишутся на `sqlite.rs:325`, читаются на `:361` и `:386`.

**Мина на пути чтения, из-за которой RED-тест может пройти вхолостую.** Обе точки чтения
превращают ошибку десериализации в «нет строк»:

```
crates/stellwerk-store/src/sqlite.rs:361-362
    serde_json::from_str(&data_json)
        .map_err(|_e: serde_json::Error| rusqlite::Error::QueryReturnedNoRows)
```

Строка, которая перестала разбираться, не падает — она **исчезает**. Значит тест «миграции»,
который проверяет только `is_ok()`, способен пройти на полностью сломанной миграции. RED обязан
утверждать число строк и восстановленное значение.

**Фикстур с риском на проводе нет ни одной.** Ни `.json`, ни `.bin`, ни `.db` в `crates/`,
`xtask/`, `tests/`; `include_bytes!` не встречается ни разу. Round-trip «сериализовали новым,
десериализовали новым» не доказывает ничего. Старый формат придётся задавать рукописным литералом
`"risk":"R3"` — как уже сделано в `core/tests/event_serde.rs`.

## Решение

Риск события — явный трёхвариантный тип, по решению владельца:

```rust
pub enum EventRisk {
    Classified(RiskClass),
    Unclassified,
    NotApplicable,
}
```

- `Classified(Rn)` — событие связано с действием известного риска;
- `Unclassified` — классификация обязательна, но не выполнена; **любое policy-решение с таким
  риском даёт `Deny`**;
- `NotApplicable` — информационное событие без действия (`Startup`, `Kanban`, heartbeat);
  **запрещён** для tool call, approval, receipt и external action.

`Option<RiskClass>` не используется: `None` не позволяет отличить «забыли классифицировать» от
«риск неприменим», и это тот же закон 6.

**`serde(default)` внутри `EventRisk` запрещён** — это прямое требование владельца и одновременно
запрет на молчаливую подстановку.

**Совместимость.** Старые строки `"risk":"R3"` обязаны читаться как `Classified(R3)`, а не ломаться
и не получать default. Механизм — рукописный `Deserialize`, повторяющий форму `risk_wire`:
принимать и голую строку, и тегированный объект.

## Радиус правки: измерен, и он означает SPLIT_REQUIRED

Заявлено «`Event.risk`: не `Option<RiskClass>`». Измерено, кто затрагивается сменой типа поля.

| Вариант | Файлов | Лимит |
|---|---|---|
| A: `EventRisk` только для `Event.risk`, `ToolRisk` не трогаем | **14** | 3 |
| B: `EventRisk` вытесняет `ToolRisk` | **22** | 3 |

`AGENTS.md:24`: «≤ 3 файла и ≤ 200 строк diff на один task packet. Больше — верни
SPLIT_REQUIRED». Оба варианта превышают лимит в 5–7 раз. Ни один из них не может быть одним
пакетом, и упаковка «ослабив тесты» не является решением — закон 2 запрещает коммит без нового
теста, а `ADR-0004` прямо фиксирует, что лимит не должен оплачиваться удалением тестов.

## Открытая развилка (только владельцу)

**Вытесняет ли `EventRisk` `ToolRisk`?**

- **A — не вытесняет.** `EventRisk` живёт только в `Event.risk`; `ToolRisk` остаётся в
  `permission.rs` и в трёх местах прода. 14 файлов. Нетронуты `permission.rs:88`
  (`Unclassified => Ok(Permission::Deny)`), `session.rs:277-279` ( receipt стирается в `None`),
  `risk_wire`. Минус: два словаря риска остаются в дереве, и `NotApplicable` не появляется в
  домене тулов — а он там и не нужен, тулы всегда действие.
- **B — вытесняет.** Один словарь риска на всё. 22 файла, затрагивает `gate.rs`, `mount.rs`,
  `permission.rs`, `session.rs` и пять их тестов. Требует отдельного решения по
  `permission.rs:88`: там `Deny` без причины, и `Unclassified` после слияния станет
  неотличим от `R5`, если тип вернётся к одному `Permission` без поля причины.

A уже даёт всё, чего требовал владелец: отсутствие данных становится различимым состоянием на
событии, и `runner.rs:535` перестаёт выдумывать R1. B меняет ещё и политику разрешений, чего
владелец не просил.

## Что НЕ входит в этот пакет

Смежное заведено находками, а не чинится здесь (закон 4). Ни одно из этих мест не требует
`EventRisk` для исправления.

- `cmd_add.rs:146` — `let risk = args.risk.as_deref().unwrap_or("R3");` Ровно запрещённая форма
  `unwrap_or`, но на `String`, а не на `RiskClass`, поэтому линтер (`plan-lint.py:135`) её не
  видит; заодно `--risk banana` запишется в `modules.toml` как есть.
- `model.rs:47` — `pub risk: Option<RiskClass>` без `#[serde(default)]`. Для `Option<T>` serde всё
  равно требует ключ, так что модуль без `risk` — это ошибка десериализации, а не `None`.
  Замаскировано тем, что `cmd_add` ключ всегда пишет.
- `session.rs:277-279` — `let ToolRisk::Classified(risk) = req.risk else { return None };`
  `receipt()` возвращает `Option<Receipt>`, и `None` означает сразу два разных исхода.
- `events.rs:72` — `.unwrap_or(RiskClass::R1)` на пустом наборе шагов.
- `permission.rs:88` — `Unclassified` и `R5` дают байт-идентичный `Permission::Deny`.
- `sqlite.rs:361` и `:386` — проглатывание ошибки десериализации в «нет строк». Это делает
  невозможной диагностику любой битой миграции, включая будущую из этого ADR.

## Последствия

- Закрывается закон 6 на событии: неизвестный риск и неприменимый риск становятся различимы и
  оба видимы в данных, а не выдаются за R1.
- Появляется новый публичный тип в `contract.rs`, который нельзя менять без нового ADR.
- Данные в существующих `events.data` продолжают читаться; при `B` меняется форма на проводе у
  `ApprovalRequest` в `.stellwerk/inbox/*.json` (`session.rs:237-241`), то есть там тоже нужна
  совместимость.
- Пока пакет не исполнен, `runner.rs:535` продолжает выдавать R1 за неизвестный риск. Это
  дефект, но он предсуществующий и не ухудшается.
