## Контекст

Четвёртая часть разреза 08 → 08a..08e. Здесь лежит самый тонкий пункт исходного пакета:
`parentToolCallId` не даёт полномочий и не является разрешением.

**Что измерено, а не выдумано.** По пробе Pi 1.0.2 (`docs/PI_1_0_2_PROBE.md`, п. a)
вложенные вызовы проходят через те же хуки `tool_call`, что и прямые, и помечаются полем
`parentToolCallId` (`agent-session.ts:629`, `:644` — дословно «`tool_call` handlers.
`parentToolCallId` is set for calls another tool made»). Значит прямой и вложенный
различаются на ВХОДЕ, а не разными политиками: один и тот же код проверки, один и тот же
набор прав.

**Почему «строже» не значит «слабее».** Требование шесть звучит как «проверять строже
прямого», а требование девять — как «та же проверка заново, с исходными правами». Противоречия
тут нет: строже может быть только ТРЕБОВАНИЕ К ВХОДУ («источник опознан»), а не сама
проверка. Поэтому у вложенного вызова ровно одна дополнительная возможность отказа —
неопознанный источник, — и ни одной дополнительной возможности пройти.

**Проверка заново, а не по наследству.** `adjudicate` не принимает ни решения родителя,
ни его набора: она принимает `&self` и одно поле из хука. Отсутствие инструмента
отменяет и вложенный вызов, и это проверяется для обоих источников в одном цикле — если
бы проверка шла только для `Direct`, тест упал бы ровно на этом.

## Что сделать

1. Дать `CallSource` двумя состояниями — `Direct` и `Nested { parent_tool_call_id }`.
2. Дать `CallSource::of(Option<&str>) -> Result<Self, IdentityError>`: `None` — прямой,
   непустой — вложенный, пустой или пробельный — `UnrecognisedSource`.
3. Принимать в `adjudicate` сырое поле, а не готовый источник, иначе неопознанный источник
   пришлось бы проверять вызывающему — и он мог бы не проверить.
4. Проверять набор инструментов одинаково для обоих источников.
5. Записывать источник в `Adjudication` — для разбора, а не для разрешения: происхождение
   видно, прав не даёт.
6. Дать `NoSuchTool` с названным набором: «нет в списке» и «нет такого инструмента вообще»
   чинятся по-разному.

## Проверка

Тест требует, чтобы решение для вложенного вызова совпало с решением для прямого по
`session` и `tool` и различалось только `source`, чтобы `parentToolCallId = "   "` дал
`UnrecognisedSource` с этим значением, а чтобы инструмент вне набора отвергался одинаково
при `None` и при `Some(parent)`. Контроль на втором обязателен: без него «отказ» мог бы
выдать источник, который проверяет только прямые вызовы. Всё остальное этого пакета —
приёмка 08e, и она проверяется там же.
