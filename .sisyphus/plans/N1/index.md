---

## Цель N1

`stellwerk run <task.toml>` выполняет ОДИН реальный запуск:

```
конфигурация запуска → отказ, если её нет → процесс в bwrap с env_clear
→ блокирующая авторизация ДО каждого защищённого вызова → gateway::decide
→ receipt в SQLite → Pi-поток разобран в RunOutcome → evidence-цепочка
→ статус «ждёт человека» → вывод в терминал
```

**Чего N1 НЕ объявляет:** `gate PASS` и `Done`. Годность прогона и приёмка
остаются за человеком (решение 5).

---

## Критерий успеха N1

**N1 доказывает цепочку на fixture-агенте:**

```
authorize → execute → receipt → evidence → ожидание Validation
```

- fixture-агент печатает корректный Pi-поток (`examples/pi-fixture.sh`),
  и по нему **измеряется** `RunOutcome` — это настоящее измерение, а не имитация;
- `ToolAttestation` появляется после фактической проверки;
- результат остаётся в состоянии «ждёт человека» — без `Validation` никогда
  не становится `Done` (решение 5);
- `blocker` при отсутствии pre-execution авторизации — **называется**, а не
  обходится (решение 6).

**Настоящий Pi появится только в N2** — вместе с model-transport.
Открытый канал между песочницей и моделью в N1 **не строится**, и это
осознанный размен, а не упущение.

## DEFERRED — N2-00: model-transport

**model-transport** — ограниченный доверенный канал между песочницей и моделью.

Проблема: `Sandbox.argv()` содержит `--unshare-net` (`sandbox_bwrap.rs:57`) —
сети нет по умолчанию. Pi без сети не получает ответа модели. Но открыть сеть
целиком означает отдать изоляцию и токен наружу.

Решение — **scoped token proxy**: агент обращается к прокси **внутри**
песочницы, настоящий токен остаётся **снаружи** в процессе Stellwerk,
наружу пропускаются только запросы к адресу модели, агенту выдаётся
короткоживущий scoped-токен вместо глобального credentials.

Текущее состояние (проверено):
- `AgentEnv::assemble` (`secrets.rs:125`) — **работает**, allowlist окружения;
- `agent_argv` (`secrets.rs:181`) — **работает**, токен уходит в argv, не в env;
- `TokenProxy` (`secrets.rs:207`) — **заготовка**: `send<F>` на строке 225
  принимает замыкание, запрос не делает;
- сетевого клиента в task-крейте **нет**: ни `TcpStream`, ни `reqwest`, ни `hyper`.

**N2-00 — первая задача N2. Security-критичный код:**
- отдельный adversarial review;
- отдельный mutation gate (≥75%, `unviable` не в знаменатель);
- **блокирует настоящий Pi smoke** — до него агент не запускается в проде;
- зависит от N1-09 как от предусловия (allowlist и границы уже зафиксированы).

В N1 `TokenProxy::send` **не реализуется** (решение владельца).

## Решения владельца (зафиксированы, обязательны для всех пакетов)

| # | Решение |
|---|---|
| 1 | `TaskSpec` **не расширяется**. Отдельная явная `ExecutionSpec` на стороне orchestration. CLI выбирает разрешённый engine-профиль; профиль сохраняется в Run. **Нет конфигурации — отказ до запуска.** Скрытый default запрещён |
| 2 | Узкий **contract-change `EngineAdapter`**: адаптер исполняет подготовленный sandbox-launch, а не создаёт голый `Command::new(program)`. Окружение и mounts/network задаются **до** spawn. Второго production-пути запуска мимо адаптера не создавать |
| 3 | Разрешена миграция `RunRequest` и точечная правка `runner.rs`. Сломанный `ShellSandbox` **не остаётся обязательным фиктивным полем**. Старый путь удаляется **только после** миграции всех потребителей. Пункты 2 и 3 — **один контракт запуска**. `lifecycle` и разбор потока не переписывать без нужды. При превышении бюджета — последовательные пакеты, каждый сохраняет компилируемый workspace |
| 4 | `Progress`/`RunOutcome` входят в N1. `/bin/echo` — smoke процесса, **не proof агентного успеха**. Fixture-stream тесты обязательны. **Настоящий Pi smoke исключён из N1** и перенесён в N2-00 как первая задача |
| 5 | Конструкторы структур **не являются authority**. `ToolAttestation` — только после фактической релевантной проверки. `Validation` — отдельное явное решение человека. **До `Validation` результат ждёт человека; `Done`/`gate PASS` не объявляются.** Тестовая `Validation` допустима только как явно помеченная фикстура |
| 6 | stdout-наблюдение **не является** pre-execution authorization. Для каждого защищённого tool call нужен **блокирующий** путь до выполнения. Нет его — назвать blocker, не имитировать проверку по логам. При отключённой сети запуск Pi использует **ограниченный доверенный model-transport**; глобальные credentials не передаются |
| 7 | Приёмка учитывает **exit code и компиляцию**, не только строки `FAILED`. Ошибка сборки или `--no-run` = FAIL. Старая baseline `473/2` не переносится без проверки текущего снимка. Mutation ≥75% на согласованной критической области + adversarial review сохраняются |

Плюс: **`stellwerk-cli` остаётся отдельным крейтом.** **TUI** — обязательная следующая
пользовательская поверхность (в N1 не входит).

## Протокол приёмки N1 (решение 7)

Приёмка пакета — **команда, которую запускает владелец сам**. Отчёт исполнителя не
является доказательством.

### Обязательные шаги (все три)

```sh
# 1. Сборка. Ошибка = FAIL, «0 тестов» = FAIL, --no-run = FAIL
cargo build --workspace --all-targets; echo "BUILD_EXIT=$?"

# 2. Тесты. Считать exit code, а не только строки FAILED
cargo test --workspace --no-fail-fast; echo "TEST_EXIT=$?"
```

**`TEST_EXIT` должен быть 0** либо совпадать с baseline ниже. Любой иной код — регресс.

### Baseline: проверен на текущем снимке

**Снимок `4e36521`, проверено фактическим прогоном:**

| Проверка | Код | Результат |
|---|---|---|
| `cargo build --workspace --all-targets` | `BUILD_EXIT=0` | сборка чистая |
| `cargo test --workspace --no-fail-fast` | `TEST_EXIT=0` | **474 passed / 0 failed / 0 ignored** |
| `cargo fmt --all -- --check` | `FMT_EXIT=0` | форматирование чистое |

**Baseline пуст: ни одного падающего теста и ни одного файла fmt.**

История: на `28af473` было `473/2` и `hexfmt.rs:75`. Владелец починил оба
между снимками — коммиты `172acb4` (F-70, восстановлен текст владельца на
строке 5410, исторические U+FFFD сохранены) и `4e17bb4` (форматирование
`hexfmt.rs`).

**Следствие для приёмки:** после N1-01 ожидается ровно то же число —
`BUILD_EXIT=0`, `TEST_EXIT=0`, `474 passed`. Любое отклонение = регресс пакета.
Сверка падающих тестов обязана вернуть **пустой** вывод:

```sh
cargo test --workspace --no-fail-fast 2>&1 \
  | grep -E '^test .* \.\.\. FAILED' | sed -E 's/^test (.*) \.\.\. FAILED/\1/' | sort -u
```

Непустой вывод = регресс. Раньше здесь был подмножественный список из двух
имён — **он больше не действует**.

**Ловушка, закрытая решением 7:** компиляционная ошибка **не порождает** строк
`test … FAILED`. Прежний протокол зелёнил бы пакет при разрушенном workspace.
Поэтому `BUILD_EXIT` и `TEST_EXIT` — обязательные, а не рекомендательные.

## Критическое условие: исполнители не подчиняются Stellwerk

Sisyphus в OpenCode имеет полный доступ к checkout. Каждый пакет несёт:

| Поле | Что требует |
|---|---|
| `acceptance` | команды владельца; учитывают exit code и компиляцию |
| `production_call` | какой символ из какого production-пути вызывается; grep-проверка «вызов вне tests/» |
| `mutation_gate` | `yes` (≥75%, `missed` считается, `unviable` не считается) / `no` (CLI-обвязка, contract-типы, крейт) |
| `forbidden_touch` | justfile, `.github/`, `scripts/plan-lint.py`, xtask-гейты |

**Зачем `forbidden_touch`:** иначе исполнитель снимет `|| true` в CI или ослабит
линтер — и пакет станет зелёным при неработающей функции.

## Установленные факты (проверено чтением исходников)

- `run_once(attempt, &dyn Worker, &impl EventStore)` — **async**, возвращает
  `CallVerdict`, **не** `RunOutcome` (`runner.rs:357`)
- `Worker::exec(workspace_ref: &str, call: &Call) -> ExecOutcome { output: String }`
  (`runner.rs:331`) — **потока нет**, разбирать stdout должен оркестратор
- `Verdict::Valid` требует `tool_steps ≥ 1`, `turns ≥ 2`, `stop == Stop` —
  считается из Pi-событий через `Progress::absorb`/`verdict_for`
- `authorize(&call, caller)` — единственный вызов `decide` (`runner.rs:279`)
- `Sandbox::command(write, program, args, budget) -> Result<Command, _>`
  (`sandbox_bwrap.rs:100`) — возвращает `Command`, `env_clear()` наносит вызывающий
- `Sandbox.argv()` содержит `--unshare-net` (`sandbox_bwrap.rs:57`)
- `EngineAdapter::session` (`m5/mod.rs:176`) спавтит сам голым `Command::new` —
  **изменяется узким contract-change (решение 2)**
- `runner.rs:18` импортирует битый `ShellSandbox`; `RunRequest` (`runner.rs:46`)
  несёт его обязательным полем — **мигрируется (решение 3)**
- `SqliteStore` реализует `EventStore` (`sqlite.rs:318`); `rusqlite` есть в
  workspace и в `store`, но **не** в `task`
- `TaskSpec` (`contract.rs:296`) полей `program`/`engine` не имеет и **не будет**
  иметь; `Default` у него нет — литералы в 5 тестах ломаются при расширении
- `TaskFileLimits::default()` даёт нули, а `validate()` требует `> 0` —
  фикстура обязана задавать `limits` явно
- `crates/stellwerk-registry/src/lib.rs` **уже существует** и экспортирует
  `pub mod cmd_audit;` и др. — замена `main.rs` на `lib.rs` не требуется
- `EvidenceEntry` (`contract.rs:449`) — ровно 6 полей; конструкторов
  `ToolAttestation`/`Validation` нет, есть только `model_claim`
- `RISK_PERMISSION` (`permission.rs:63`) — таблица по `RiskClass`, **не** по именам
  инструментов; источника «инструмент → класс», кроме `modules.toml`, нет
- `bwrap` 0.13.0, `cargo-mutants`, `just` 1.58.0, `jq` 1.8.2 — установлены
