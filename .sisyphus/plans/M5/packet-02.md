## Контекст

Pi — сменный движок, а не единственный. OpenCode, Codex и Claude Code подключаются тем
же интерфейсом позже, в M6. Если интерфейс написать под один движок, подмена станет
правкой каждого вызывающего — а это ровно та ошибка, которую потом не найти.

Критичность: движок решает, что вообще будет исполнено, поэтому мутационный порог
в 80% обязателен с этого пакета, а не «когда-нибудь».

## Что сделать

0. Этот пакет единственный владелец `crates/stellwerk-task/src/lib.rs` в M5:
   добавление модуля требует его правки, а файл общий с M2 и M4, поэтому порядок
   объявлен в `depends_on`. Следующие пакеты расширяют `engine/mod.rs` и его больше
   не трогают.

1. `Engine` — трейт с двумя обязанностями: `probe()` возвращает доступность движка с
   причиной, `session(argv, cwd, timeout)` запускает одну сессию и возвращает поток
   результата. Больше ничего: бюджеты, песочница и одобрение — не забота движка.
2. `ProbeReport { engine, available, reason }`. Поле причины обязательно: «недоступен»
   без причины бесполезен при разборе инцидента.
3. `PiEngine` — реализация поверх списка аргументов, без shell. Проверка доступности
   ищет бинарь и сверяет версию с запиненной.
4. Никаких побочных эффектов при создании движка: конструктор не запускает процессы.
   Иначе невозможно собрать список доступных движков, не запустив их все.
5. Реализация не читает и не пишет файлы вне переданного `cwd`.

## Проверка

Тест подставляет поддельный путь к движку и требует `available=false` с непустой причиной;
для заведомо работающего пути требует `available=true`. Ни один тест не запускает Pi.
