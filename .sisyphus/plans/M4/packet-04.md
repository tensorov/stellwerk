## Контекст

- В M2-04 `watch` — честная заглушка с кодом 1 и текстом
  `not implemented: watch (packet-12)`. Этот пакет заменяет **только `watch`**;
  `cancel` и `logs` остаются заглушками и указывают на свои пакеты.
- `watch` читает `EventStore::list_by_task`. Трейт уже есть в
  `stellwerk-store/src/traits.rs`; реализация — SqliteStore из M2-12.
- **Зависит от M2-12:** без записи событий команде нечего показывать. Раздавать
  раньше нельзя — это неисполнимость по существу, а не задержка по времени.

## Что сделать

1. `watch <id>`: `EventStore::list_by_task(&id)`. Пустой список — код 0 и
   `no events for <id>` на stdout, **не** код 1: отсутствие событий для
   существующей задачи — это факт, а не ошибка.
2. Печать по одному событию на строку в порядке, который отдаёт трейт. Формат
   строки: `<timestamp> <kind> <краткое описание>`. Время и kind берутся из
   `Event`, ничего не выдумывается.
3. Отсутствующая задача — код 1, как у `get`. **Существующая задача без событий —
   код 0.** Различать эти два случая обязательно, иначе `watch` на только что
   созданной задаче выглядит как ошибка.
4. Убрать заглушку `watch` из `run` и обновить её текст, если он где-то
   перечислен как «не реализовано». `cancel` и `logs` не трогать.
5. **`tests/cli_watch.rs` — новый сценарий, пакет создаёт его сам.** Файл уже
   объявлен в `files_allowed`, но ни один из пунктов 1–4 не велит его создать,
   а отдельной красной половины у `watch` нет: `M2-04` оставил только заглушку.
   Без этого пункта пакет выглядит зелёным, а команда приёмки падает с кодом
   101 (`no test target named cli_watch`) — то есть «0 failed» утверждало бы
   не о пакете, а о его отсутствии.

   > **Правка 2026-09-29 (F-47).** Пункт добавлен, потому что отзыв F-43
   > установил: тело пакета задаёт поведение полностью — оба кода возврата,
   > текст stdout, формат строки — и пакет исполним. Не хватало ровно одного
   > шага. Сравните `M4/packet-08`, где первый пункт прямо начинается со
   > «`tests/vertical.rs` — **новый** сценарий».

   Сценарий обязан покрыть все три различия, иначе пакет доказывает половину:
   - существующая задача **с** событиями → код 0, по строке на событие в
     формате `<timestamp> <kind> <краткое описание>`, порядок как отдаёт трейт;
   - существующая задача **без** событий → код 0 и `no events for <id>` на
     stdout, **не** код 1 (закон 6: отсутствие данных — факт, а не отказ);
   - отсутствующая задача → код 1 как у `get`, и этот случай обязан отличаться
     от предыдущего, иначе `watch` на только что созданной задаче неотличим от
     ошибки.
