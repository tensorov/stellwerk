## Регистрация модуля — ТОЛЬКО инлайн-форма

`lib.rs` объявляет `gate`, `mount`, `permission`, `receipt`, `session`, `shaping`.
Каталога `src/llm/` в крейте нет.

**Проверено пробой rustc 2026-10-06:** `pub mod llm;` при `src/llm/scheduler.rs` даёт
`error[E0583]: file not found for module 'llm'` — форме `mod` нужен либо `src/llm.rs`,
либо `src/llm/mod.rs`, а это ТРЕТИЙ файл сверх `lib.rs` и теста, и ADR-0003 его не даёт.
Инлайн-форма `pub mod llm { pub mod scheduler; }` в `lib.rs` компилируется ровно двумя
файлами. Форму `pub mod llm;` в этом пакете использовать нельзя.

## Контекст

I13: ≤3 потока, ≤30 req/min суммарно с ретраями. Стабильный префикс обязателен: при
нестабильном кэше стоимость растёт, а провайдерский лимит считается по запросам, а не
по токенам, поэтому ретраи способны исчерпать лимит сами по себе.

## Что сделать

1. ≤3 одновременных потока; общий limiter 30 req/min на все потоки ВКЛЮЧАЯ ретраи.
2. Стабильный префикс: system + схемы в начале, новое в конец. Никаких nonce,
   меток времени и идентификаторов прогона в префиксе.
3. TTFT-таймаут отдельным значением: медленный первый байт и зависший стрим —
   разные состояния, и их различие обязано быть выражено в типе статуса.
4. Метрики cache-hit и TTFT пишутся. Если их нечем наполнить — пишется «нет данных»,
   а не ноль (I2).

ADR-0011 в этот пакет НЕ входит: файла в `files_allowed` нет, третий слот занят
`lib.rs` и тестом.

## Проверка

Обязателен тест на 3 потока без 429 при включённом лимите, и отдельный — что ретрай
СЧИТАЕТСЯ в лимит. Тест без второго пункта проходит и при ретраях вне лимита.
