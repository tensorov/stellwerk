# ADR-0020: TLS-транспорт для хостового backend — rustls и webpki-roots

Статус: принят
Дата: 2026-10-21
Пакет: N2-00g1
Связано: ADR-0018 (точные пины TUI-зависимостей), AGENTS.md (закон 5 — зависимости только из `[workspace.dependencies]`; закон 6 — отсутствие данных не значение по умолчанию)

## Проблема

Хостовому `ModelBackend` нужен HTTPS-клиент: модельный трафик Pi идёт через `model.sock` в хост, и только хост имеет сеть. Песочница остаётся с `--unshare-net`, токен в неё не попадает.

Но токен живёт в `secrets.rs` как приватное поле `Token`: ни `Display`, ни аксессора, ни `Clone` наружу значения. Единственный законный способ отправить запрос — `TokenProxy::send`, который сам собирает **готовый HTTP-wire** (`METHOD path HTTP/1.1`, `authorization: Bearer …`) и передаёт его transport-замыканию `FnOnce(&str) -> Result<(u16, String), String>`.

Значит транспорт обязан принимать байты запроса как есть. Это и есть ограничение выбора: HTTP-клиент, который строит запрос сам, до токена не дотянется иначе как через новую дыру в границе секрета.

## Ключевые факты

1. **`ureq` и `reqwest` не подходят по форме шва, а не по качеству.** Оба принимают метод, URL, заголовки и тело как параметры и собирают запрос внутри. Чтобы отдать им токен, пришлось бы добавить в `secrets.rs` аксессор или `Display` — то есть ослабить ровно тот инвариант, ради которого файл существует. Запрет дешевле проверки: у `Token` нет даже `Display`, поэтому случайный `format!("{token}")` секрет не напечатает.
2. **Системный `curl` тоже не подходит.** Он не принимает готовый HTTP-запрос как байты: запрос собирается из флагов, и токен пришлось бы передать аргументом или файлом — и то и другое уже закрыто (`TokenInArguments`, `ConfigInsideSandbox`). Плюс версия `curl` на машине стала бы частью контракта.
3. **Дефолтные фичи `rustls` 0.23 тянут `aws-lc-rs`** — сборочную зависимость на cmake/nasm, которой на dev-станции и в CI нет. `ring` собирается `cc`, а `cc` уже требуется транзитивно.
4. **Корни сертификатов должны быть данными.** `rustls-native-certs` читает системный store во время выполнения; непрочитанный store вернул бы «нет доверия» без причины, а это подмена «нет данных» отказом (закон 6). `webpki-roots` кладёт корни в крейт.
5. **TLS 1.2 включается явно.** Если провайдер говорит только 1.2, отказ «не поддерживается версия» и «сервис недоступен» — разные инциденты; выключенный по умолчанию `tls12` сделал бы второй неотличимым от первого.

## Решение

1. В `[workspace.dependencies]` добавлены ровно два крейта, оба — точный пин:

       rustls       = { version = "=0.23.46", default-features = false, features = ["ring", "std", "tls12"] }
       webpki-roots = "=1.0.10"

   Резолв в `Cargo.lock`: `rustls 0.23.46`, `rustls-pki-types 1.15.1`, `rustls-webpki 0.103.16`, `ring 0.17.14`, `webpki-roots 1.0.10`. Дублей `rustls` в дереве нет (`cargo tree -p stellwerk-task -d` пуст).

2. `crates/stellwerk-task/Cargo.toml` подключает оба через `{ workspace = true }` — единственный санкционированный способ (закон 5). Версии живут в одном месте.

3. **`tokio` не получает новых фич.** Транспорт синхронный (`std::net::TcpStream` + `rustls::StreamOwned`): `ModelBackend::turn` синхронный, и превращать его в async ради TLS значило бы переписать `model_transport.rs`, который этот пакет не трогает.

4. **Проверка сертификата обязательна.** `dangerous()` не используется ни в одном варианте; SNI берётся из host базового URL.

5. **Область пакета — только зависимости и этот ADR.** Расширение `TokenProxy::send` телом запроса — N2-00g2, реализация backend — N2-00g3.

## Что запрещено

1. `cargo add`; манифест правится вручную, версии выбраны до записи.
2. Диапазонные версии для этих двух крейтов: только `=x.y.z`, как в ADR-0018.
3. `native-tls`, OpenSSL, `rustls-native-certs`: системный store и версия OpenSSL не должны становиться частью поведения.
4. Добавление фич `tokio` (`net`, `tls`) под этот пакет.
5. Третий TLS-крейт или второй HTTP-клиент в том же пакете — только новым пакетом с `contract-change`.

## Когда пересматривается

При обновлении `rustls` или `webpki-roots` (сверяется резолв в `Cargo.lock`), при появлении у `secrets.rs` иного шва, кроме готового wire, либо если backend переедет из `stellwerk-task` в отдельный крейт. Любое из этих событий — отдельный пакет с `contract-change` и ADR.
