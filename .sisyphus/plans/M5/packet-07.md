## Контекст

Исполнять код агента в рабочем дереве нельзя: прогон способен испортить то, что потом
аттестуется. Песочница обязана быть без прав root, потому что машина — клиент без
sudo, и решение «дать root» там невозможно в принципе.

`bwrap` выбран владельцем как движок по умолчанию: user namespaces, один бинарник,
никакого демона. Второй движок появится в M6 за интерфейсом.

## Что сделать

1. Сборка аргументов `bwrap` списком: отдельный каталог рабочей копии, только чтение
   системных каталогов, отдельный каталог для временных файлов, без сети.
2. Проверка пути **до** запуска: путь, уходящий за пределы рабочего каталога после
   нормализации `..`, отвергается с внятной причиной. Проверка после запуска не считается
   защитой: запись уже произошла.
3. Отсутствие истории: песочница собирается из выгрузки состояния, и `.git` в ней нет
   физически. Копирование с сохранением истории запрещено.
4. Таймаут в песочнице не подменяет таймаут исполнения: это разные вещи, и путать их
   значит терять частичные данные при убийстве группы процессов.
5. Модуль не читает конфигурацию из окружения напрямую: песочница получает её от
   вызывающего, иначе один и тот же запуск даёт разный результат в разных терминалах.

## Проверка

Тест запускает настоящий `bwrap` в изоляции, если он есть в системе, и требует отказа
на внешний путь, пустого `.git` внутри и успеха на внутреннем пути. При отсутствии
`bwrap` тест падает явно: отсутствие движка — не повод объявлять проверку зелёной.
